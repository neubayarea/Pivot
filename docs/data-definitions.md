# Pivot 数据定义说明

> 版本 v0.2 初稿 · 2026-10-23（v0.2：按业界做法和研究修订压迫、反击、评分起点和场外影响，见第 9 节） · 负责：B（模拟）、D（AI 内容与质量）· 任务 B15
> 字段的格式以代码为准：`packages/pivot_core/src/pivot_core/domain/`。本文规定**字段里的值怎么来**：每种事件什么时候产生、每个判断用什么阈值、每个指标怎么算。

## 0. 怎么用这份文档

- **谁按它做**：模拟器（B03、B11、B12、B14）产生数据时按它判断；统计员（B05）按它计算；核查员（D05）按它核对；前端和 AI 按它解释含义。三方理解必须一致。
- **编号**：每条定义有一个编号，前缀表示类别：

  | 前缀 | 类别 |
  |---|---|
  | `CONV` | 基础约定 |
  | `EVT` | 事件 |
  | `ATTR` | 判断类字段 |
  | `MET` | 统计指标 |
  | `RAT` | 单场评分 |
  | `CTX` | 场外与环境影响 |
  | `QA` | 数据质检规则 |

- **定义即测试**：每条定义至少对应一个单元测试，测试函数名带上编号，例如 `test_attr_001_under_pressure_radius`。改定义必须同时改测试；测试不过，说明代码和定义对不上。
- **用词**：“必须”是硬性规则，违反就是错误数据；“应该”是默认做法，有理由可以例外，但要在代码里注释原因。
- **参照标准**：能对上业界公认做法的，直接采用并注明出处（StatsBomb 开放数据规范、Opta / Stats Perform 定义、Wyscout 定义、SPADL）；只有合成数据才有的（例如传球难度、影响清单），注明“Pivot 自定”。
- **数值都是初稿**：阈值和权重是按业界常见做法提出的初始值，标“可调”的，要在标定（B07）后确认，确认后把本文版本升到 v1.0。

## 1. 基础约定

### CONV-001 坐标系

- 球场统一换算为 **105 × 68 米**（SPADL 约定）。真实球场尺寸不同，但坐标一律按标准尺寸记录（StatsBomb、Opta 的做法相同）。
- 原点在主看台视角的左下角。x 沿球场长边，y 沿宽边。
- **主队始终向 x = 105 进攻，客队始终向 x = 0 进攻，上下半场都不换边**。这是数据约定，不代表真实比赛不换边。前端显示时可以自行翻转。
- 坐标保留到 0.1 米。

### CONV-002 进攻方视角

- 所有“前场 / 后场”“左 / 右”“本方禁区 / 对方禁区”的判断，都从**做动作那一方的进攻方向**来看。
- 换算方法：主队坐标不变；客队坐标换成 (105 − x, 68 − y)。换算后，本方球门在 x = 0，对方球门在 x = 105，y = 0 是本方的右边线。
- 代码：`attacking_view()`。

### CONV-003 时间

| 字段 | 含义 |
|---|---|
| `t` | 从第一次开球起**累计的比赛秒数**，补时、加时、点球大战都算在内，中场休息不算。必须全场唯一、只增不减。 |
| `period` | 阶段：1 上半场，2 下半场，3 加时上半场，4 加时下半场，5 点球大战（与 StatsBomb 编号一致）。 |
| `period_t` | 本阶段开球后经过的秒数。 |
| `minute` | `t // 60`，从 0 开始的累计分钟。所有统计窗口、每分钟指标、快照都用它。 |
| `clock_label` | 给人看的时钟，例如 `63'`、`45+2'`、`120+1'`、`PEN`。只用于显示，**禁止**用来做计算。 |

- 规则：一个阶段的常规时长是上下半场各 45 分钟、加时各 15 分钟；`period_t` 超过常规时长的部分就是补时。
- 例子：没有上半场补时的情况下，下半场 17:30 时，`t = 2700 + 1050 = 3750`，`minute = 62`，`clock_label = 63'`。

### CONV-004 编号

- `event_id` 格式为 `m{minute:03d}-s{seq:05d}`，例如 `m062-s01042`；界面显示为 `#1042`。
- `seq` 是全场递增的事件序号。同一秒内的多个事件按 `seq` 定先后。
- 球员编号 `h07` 表示主队 7 号，`a11` 表示客队 11 号。

### CONV-005 控球与控球段

- **控制球**：球员能有意识地处理球，即完成接球、带球，或者作为传球、射门的发起人。被球打到、挡出、蹭到都不算控制。
- **控球段（possession）**：从一方控制球开始，到另一方控制球为止。对方短暂碰球但没有控制（封堵、挡出、蹭到），**不**中断控球段（与 StatsBomb 的 possession 定义一致）。
- 球出界、犯规、越位之后，由定位球重新开始的一方开启新的控球段；如果还是原来那一方，控球段编号不变。
- `possession_id` 从 1 开始，每次换手加 1。

### CONV-006 球在比赛中 / 不在比赛中

- 球出界、裁判鸣哨、进球后到重新开球之前，球都**不在比赛中**。
- 球不在比赛中的时段，追踪帧照常输出，但 `possession` 为 `null`，这段时间不计入控球率。

### CONV-007 追踪帧

- 每秒一帧，`t` 与事件共用同一个时钟。事件发生的那一秒，球员位置取 `t` 相同的那一帧。
- 每帧只包含**在场**的球员，最多 22 人；被罚下和被换下的球员不出现。
- `speed_ms` 是从上一帧到这一帧的位移除以 1 秒。
- `fitness` 取 0 到 1，开场时等于赛前状态里的体能。

### CONV-008 网格与战术区域

| 名称 | 规则 |
|---|---|
| 威胁网格 | 16 列 × 12 行，每格约 6.6 × 5.7 米，按原始坐标计算（`zone_of()`） |
| 三分之一 | 进攻方视角下 x < 35 为后场，35 ≤ x < 70 为中场，x ≥ 70 为前场 |
| 纵向通道 | 进攻方视角下，按 y = 13.84、24.84、43.16、54.16 分成五条：右边路、右肋部、中路、左肋部、左边路。边界正好是禁区和小禁区的边线延长线 |
| 禁区 | 距底线 16.5 米以内，且 13.84 ≤ y ≤ 54.16 |
| 小禁区 | 距底线 5.5 米以内，且 24.84 ≤ y ≤ 43.16 |

## 2. 事件定义

**通用规则**：

- 每个事件都有 `team`，表示做动作的一方。
- `outcome` 只用于结果有成败之分的事件：传球、带球、过人、对抗、抢断。其他事件不填。
- 有因果关系的事件之间，必须通过 `related_event_ids` **双向**关联。

### EVT-001 传球 `pass`

- **定义**：球员有意把球踢、顶、扔给队友或某个区域。包括所有定位球的第一脚（角球、任意球、界外球、球门球、开球），以及门将手抛球、大脚开球。
- **起点**：出球那一刻球的位置。**终点**：球被下一个人碰到，或者出界、停下的位置。
- **成功**：球被**本方**队员控制（CONV-005）。被对手碰到、出界、越位都算失败。
- **必填**：`player_id`、`location`、`end_location`、`outcome`、`pass_type`、`pass_height`、`body_part`、`ball_speed_kmh`、`success_prob`。成功的传球还必须填 `receiver_id`。
- **关联**：直接导致射门的传球，必须和那次射门互相关联（ATTR-010）。
- **对应**：StatsBomb Pass（不单独产生 Ball Receipt 事件，接球人记在 `receiver_id`）；SPADL pass / cross / 各类定位球。

### EVT-002 带球 `carry`

- **定义**：球员控球移动，**位移至少 3 米**，期间没有对手争抢（StatsBomb 对 Carry 不设最小距离，我们设 3 米，避免产生大量原地碎事件）。
- 中途被抢断的，记为带球加上对方的一次抢断，带球本身的 `outcome` 为失败。

### EVT-003 过人 `dribble`

- **定义**：持球人试图从**正面对抗的对手**身边过去。
- **成功**：过掉对手后仍然控制着球。
- 必须和防守方的 `duel` 事件互相关联。
- **对应**：StatsBomb Dribble 与 Dribbled Past；SPADL take_on。

### EVT-004 射门 `shot`

- **定义**：有意把球射向对方球门的动作，包括头球和点球。
- `shot_outcome` 的取值：

  | 值 | 含义 |
  |---|---|
  | `goal` | 球整体越过门线，进入两门柱之间、横梁以下 |
  | `saved` | 本来会进门框范围，被门将扑出或扑住 |
  | `blocked` | 被**外场球员**挡下（包括门线上的解围） |
  | `post` | 打中门柱或横梁，没有进 |
  | `off_target` | 偏出或高出 |

- 射正（`shots_on_target`）= `goal` + `saved`。中柱不算射正，和 Opta 一致。
- **必填**：`xg`（ATTR-008）、`body_part`、`ball_speed_kmh`、`end_location`、`shot_end_height_m`、`keeper_location`。
- 点球大战的射门：`period = 5`、`play_pattern = "penalty"`，并且必须填 `shootout_round`。点球大战的射门**不计入**任何比赛统计（MET 全部排除第 5 阶段）。
- 乌龙球不是射门，记在防守方的 `clearance` 或 `block` 上，`meta.own_goal = "true"`。

### EVT-005 门将 `goalkeeper`

- **定义**：门将用手或身体处理射门或传中的动作。`keeper_action` 取值：

  | 值 | 含义 |
  |---|---|
  | `shot_saved` | 扑住，没有脱手 |
  | `shot_parried` | 扑出，球弹回场内 |
  | `tipped_over` | 托出底线或横梁 |
  | `goal_conceded` | 射门进了，门将有动作但没碰到或没挡住 |
  | `claim` | 接住传中球 |
  | `punch` | 拳击解围 |
  | `sweep` | 出禁区拦截 |
  | `smother` | 扑在对方脚下 |
  | `pick_up` | 接住回传或滚地球 |

- `keeper_technique`：`standing` 站立、`diving` 鱼跃、`reflex` 近距离反应。
- 每次门将处理射门的事件，都必须和那次射门互相关联。
- **对应**：StatsBomb Goal Keeper（type、technique）。

### EVT-006 压迫 `pressure`

- **定义**：防守球员向持球人、准备接球的人，或正在出球的人逼近，并进入 **4.6 米（5 码）以内**。对方是门将时，放宽到 **9.1 米（10 码）**。与 StatsBomb 的压迫事件一致（参考资料 [1]）。
- 同一名防守球员对同一名持球人，**2 秒内只记一次**。
- 被压迫的那个动作，`under_pressure = true`（ATTR-001），并且和压迫事件互相关联。
- 丢球后 5 秒内的压迫，`counterpress = true`（ATTR-002）。

### EVT-007 对抗 `duel`

- **定义**：双方各一名球员同时争夺一个无人控制的球，或者正面一对一争抢。
- `duel_type`：
  - `aerial`：球离地超过 **1.5 米**、双方都有争顶动作；
  - 其余为 `ground`。
- **成功**：本方得到球或者破坏了对方的控制。
- 每次对抗产生两个事件，双方各一个，结果相反，互相关联。

### EVT-008 抢断 `tackle`

- **定义**：防守球员从持球人脚下把球抢走或捅走。
- **成功**：本方得到球，或者球离开了对方控制（StatsBomb 对 Duel-Tackle 的结果分为 Won 和 Lost）。

### EVT-009 拦截 `interception`

- **定义**：读出对方传球线路，在传球途中截下。
- 必须和被拦截的那次传球互相关联，那次传球为失败。

### EVT-010 解围 `clearance`

- **定义**：在本方危险区域里把球踢走或顶走，目的不是传给队友，而是解除危险。
- 门线解围也记为解围。如果解围的是一次射门，还要另记一次 `block`。

### EVT-011 封堵 `block`

- **定义**：外场球员用身体挡下对方的传球或射门。
- 挡下射门时，那次射门的 `shot_outcome = "blocked"`。

### EVT-012 夺回球权 `ball_recovery`

- **定义**：拿到一个**无人控制的球**（解围后的落点、弹出来的球），并开启本方的控球段。

### EVT-013 犯规 `foul`

- **定义**：裁判判罚的违规行为，记在**犯规方**。
- 必须填 `foul.foul_type`、`foul.advantage_played`、`foul.penalty_awarded`。
- 出牌时同时产生一个 `card` 事件，两者互相关联。

### EVT-014 出牌 `card`

- **定义**：裁判出示黄牌或红牌。必须填 `foul.card` 和 `foul.card_reason`。不是因为犯规出的牌（例如抗议、拖延时间），`foul_type` 填 `dissent` 或 `time_wasting`。
- 第二张黄牌记为 `second_yellow`，并且立即罚下。

### EVT-015 越位 `offside`

- **定义**：传球那一刻，接球人站在越位位置，并且参与了进攻。记在**进攻方**，和那次传球互相关联，那次传球为失败。
- 越位位置：在对方半场、比球更靠近对方底线，并且比对方倒数第二名球员（通常是最后一名后卫，门将算一名）更靠近底线。用传球那一秒的追踪帧判断。

### EVT-016 VAR 复核 `var_review`

- **定义**：视频助理裁判对进球、点球、直接红牌或认错人进行复核。
- 必须填 `var`：复核了什么、复核的是哪个事件、维持还是改判、原因、用时。
- 改判进球时，那次射门的 `shot_outcome` **保持原样**（保留历史），比分通过这个复核事件更新。统计时，被改判无效的进球不算进球，但仍算一次射门。

### EVT-017 受伤 `injury`

- **定义**：球员受伤，比赛因此暂停或者他需要治疗。必须填 `injury`。
- `can_continue = false` 时，同一方必须在 **120 秒内**出现一次 `substitution`，原因为 `injury`；换人名额用完的情况除外，这时该队少一人比赛。

### EVT-018 换人 `substitution`

- 必须填 `substitution`（谁下、谁上、顶哪个位置、原因），以及换人后完整的 `team_sheet`。
- 每队常规时间最多换 5 人，加时可以多换 1 人（现行竞赛规程的常见做法）。

### EVT-019 阵型调整 `tactical_shift`

- **定义**：教练改变阵型或战术，但没有换人。必须填新的 `team_sheet` 和 `tactics`。
- 只改个人指令也记为阵型调整。

### EVT-020 开球 `kickoff`

- 每个阶段开始、每次进球后的开球都记一次。
- 比赛第一次开球必须带上双方的 `team_sheet` 和 `tactics`。

### EVT-021 补时公布 `added_time`

- 第四官员举牌时记录，填 `added_minutes`。上半场和下半场各一次；加时赛按需要。
- 实际补时可以比公布的长，但**不能**比公布的短。

### EVT-022 阶段结束 `period_end`

- 每个阶段结束时记一次。

## 3. 判断类字段

### ATTR-001 是否被压迫 `under_pressure`

- 动作发生的那一秒，满足下面任一条件即为 `true`：
  - 有对手在持球人 **2 米**以内（与 Driblab 的“被压迫”一致，参考资料 [3]）；
  - 有对手在 **4.6 米**以内（与 EVT-006 的压迫半径一致），并且正以 **1 米/秒以上**的速度靠近持球人（沿用基于追踪数据的压迫研究，参考资料 [2]）。
- 只看距离会把“站在旁边但没有上抢”的人也算进去，所以第二条要求对手正在靠近。

### ATTR-002 反抢 `counterpress`

- 本队**失去球权后 5 秒内**做出的压迫、抢断、对抗、拦截、犯规，标为 `true`。与 StatsBomb counterpress 的定义相同。

### ATTR-003 控球怎么开始的 `play_pattern`

- 按开启这个控球段的方式来定：角球、任意球、界外球、球门球、开球、点球，各自对应一个值。
- **反击 `counter`**：同时满足以下四条。
  1. 在**本方半场**（进攻方视角 x < 52.5）赢得球权，与 Opta“快速反击”的起点一致（参考资料 [4]）；
  2. 赢得球权后 **10 秒内**把球带进或传进前场三分之一（x ≥ 70）；
  3. 这段时间里传球**不超过 4 次**（“传球次数少”是英格兰足总对反击的描述，参考资料 [6]）；
  4. 进入前场的那一秒，对方在球和本方进攻球门之间的**外场球员不超过 5 人**，用来近似 Opta 所说的“对方防守尚未落位”。
- 业界没有公布统一的秒数和传球次数标准（Opta 只给出文字定义，StatsBomb 的 From Counter 由人工判断，参考资料 [4][5]），第 2 到第 4 条的数字是 Pivot 自定的，可调。
- 和 Opta 的“快速反击”不同，我们的反击**不要求以射门结束**；需要“以射门结束的反击”时，在统计里另外筛选。
- 其余为运动战 `open_play`。
- 同一个控球段内的所有事件，`play_pattern` 都相同。

### ATTR-004 传球类型 `pass_type`

按下表**从上到下**取第一个符合的：

| 值 | 判断规则 | 出处 |
|---|---|---|
| 定位球各类 | 由定位球重新开始比赛的那一脚 | 通用 |
| `keeper_throw` / `keeper_kick` | 门将用手抛出，或从手中开大脚 | StatsBomb |
| `cross` | 起点在前场、中路以外（两条边路或两个肋部，即进攻方视角 x ≥ 70，并且 y < 24.84 或 y > 43.16），终点在对方禁区 | Opta 传中 |
| `cutback` | 起点距对方底线 6 米以内、在禁区宽度以内或附近，球往回传（终点 x < 起点 x），终点在禁区内 | 通用 |
| `through_ball` | 球从对方最后一名后卫的身后穿过（终点比对方倒数第二人更靠近底线），并且接球人原本在他身前或与他平行 | StatsBomb |
| `switch` | 横向移动超过 **34 米**（球场宽度的一半） | StatsBomb |
| `long_ball` | 传球距离 **32 米**以上 | Opta 长传 |
| `back_pass` | 传给本方门将 | 通用 |
| `regular` | 以上都不是 | — |

### ATTR-005 传球高度 `pass_height`

| 值 | 判断规则 |
|---|---|
| `ground` | 全程不离开地面 |
| `low` | 离地，但最高点低于 **1.6 米**（大约肩高） |
| `high` | 最高点不低于 1.6 米 |

与 StatsBomb 的 Ground / Low / High 一致。

### ATTR-006 弧线 `delivery`

- 只用于传中、角球，以及踢进禁区的任意球。
- `inswing` 内旋（弧线朝球门方向）、`outswing` 外旋（弧线远离球门）、`straight` 直线。
- 由主罚人的惯用脚和出球位置决定：从右侧用左脚，或从左侧用右脚，是内旋；反之是外旋。也可以由战术里的定位球套路指定。

### ATTR-007 成功概率 `success_prob`

- 模拟器在决定结果**之前**算出的成功概率，取 0 到 1。
- **传球难度** = 1 − `success_prob`。
- 在真实数据里，这个值要靠模型估计（Opta 的 xPass）；在我们的模拟世界里，它是**真实值**（Pivot 自定）。

### ATTR-008 预期进球 `xg`

- 模拟器决定射门结果时用的**进球概率**，由射门距离、角度、部位、挡在前面的人数、门将站位、是否被压迫、射手能力决定。
- 和 `success_prob` 一样，在模拟世界里它是真实值。
- 点球的 `xg` 固定为点球进球率的标定值，约 0.76，可调。
- MET 统计中的 `xg` 包含点球（不含点球大战）。

### ATTR-009 威胁值 `threat`

- 按 Karun Singh 的期望威胁（xT）方法：在 16 × 12 网格上，用模拟器离线跑 1,000 场比赛，算出“从这一格出发，控球段最终进球的概率”。
- 成功的传球和带球，`threat = xT(终点格) − xT(起点格)`，可以是负数。失败的动作 `threat = 0`。
- 威胁网格随模拟器版本更新，版本号记在 README。

### ATTR-010 关键传球、助攻、二次助攻

- **关键传球**：一次传球之后，接球人**不再经过其他队友**就完成了射门。这次传球和这次射门互相关联。与 StatsBomb shot_assist、Opta key pass 一致。
- **助攻**：关键传球之后的射门进了。
- 中间只隔了接球人自己的带球或过人，仍然算关键传球；中间如果有对手**控制**过球，就不算。

### ATTR-011 推进传球、推进带球

采用 Wyscout 的定义，按进攻方视角，计算“到对方球门中点的距离”缩短了多少：

| 起点和终点 | 至少缩短 |
|---|---|
| 都在本方半场 | 30 米 |
| 从本方半场到对方半场 | 15 米 |
| 都在对方半场 | 10 米 |

- 只算**成功**的传球和带球。角球、界外球不算。

### ATTR-012 进入禁区、进入前场

- **进入禁区**：一次成功的传球或带球，起点不在对方禁区，终点在对方禁区。
- **进入前场**：同理，起点不在前场三分之一，终点在前场三分之一。

### ATTR-013 球速 `ball_speed_kmh`

- 出球瞬间的初速度，单位公里每小时。
- 射门速度是射门的初速度；德甲 Match Facts 公布的“射门速度”就是这个值。

## 4. 统计指标

**通用规则**：

- 窗口 `window = (a, b)` 是累计分钟的左闭右开区间，即 `a ≤ minute < b`。
- 第 5 阶段（点球大战）的事件**全部不计入**统计。
- `team` 指被统计的一方；`player_id` 不为空时，只统计这名球员。
- 百分比保留 1 位小数，距离保留 1 位小数，次数是整数。
- 计算由 `StatCalculator` 完成，核查员调用同一个函数，**禁止**另写一套算法。

| 编号 | 指标 `metric` | 计算方法 | 单位 |
|---|---|---|---|
| MET-001 | `possession_pct` | 窗口内，追踪帧里 `possession` 为本队的秒数 ÷ `possession` 不为空的秒数 × 100 | % |
| MET-002 | `passes` | 传球次数，含成功和失败，不含界外球 | 次 |
| MET-003 | `pass_accuracy_pct` | 成功传球 ÷ 传球 × 100，不含界外球（与 Opta 一致） | % |
| MET-004 | `passes_final_third` | 终点在对方前场三分之一的**成功**传球 | 次 |
| MET-005 | `box_entries` | 进入禁区的次数（ATTR-012） | 次 |
| MET-006 | `shots` | 射门次数 | 次 |
| MET-007 | `shots_on_target` | `shot_outcome` 为 `goal` 或 `saved` 的射门 | 次 |
| MET-008 | `xg` | 射门 `xg` 之和 | xG |
| MET-009 | `threat_total` | 本队事件 `threat` 之和 | 指数 |
| MET-010 | `pressures` | 压迫事件次数 | 次 |
| MET-011 | `tackles_won` | 成功的抢断 | 次 |
| MET-012 | `interceptions` | 拦截次数 | 次 |
| MET-013 | `duels_won` | 成功的对抗，含空中和地面 | 次 |
| MET-014 | `turnovers` | 本队的控球段因为本队失误结束的次数：失败的传球、带球、过人，或被抢断。射门、出界后由对方发球、阶段结束不算 | 次 |
| MET-015 | `momentum_avg` | 窗口内每分钟势头的平均值（ADR-0010），以本队视角取正负：客队取相反数 | 指数 |
| MET-016 | `line_height_m` | 本队**不控球**的每一帧里，场上后卫（当前位置为 LB、CB、RB、LWB、RWB）到本方球门线的平均距离，再对这些帧取平均 | 米 |
| MET-017 | `team_width_m` | 本队**控球**的每一帧里，10 名外场球员 y 坐标的最大值减最小值，再对这些帧取平均 | 米 |
| MET-018 | `press_distance_m` | 对方控球且有持球人的每一帧里，持球人到本队最近球员的距离，再对这些帧取平均 | 米 |
| MET-019 | `distance_covered_km` | 本队所有球员相邻两帧之间位移的总和 ÷ 1000；指定球员时只算他一人 | 公里 |
| MET-020 | `progressive_passes` | 推进传球次数（ATTR-011） | 次 |
| MET-021 | `ppda` | 对方在**它自己的后 60%** 区域（对方视角 x < 63）的传球次数 ÷ 本队在同一区域的防守动作次数（抢断、拦截、犯规、对抗）。分母为 0 时为空。Colin Trainor 提出的标准算法 | 比值 |
| MET-022 | `xa` | 本队（或这名球员）关键传球所引出的射门 `xg` 之和（Opta xA） | xG |
| MET-023 | `field_tilt_pct` | 本队起点在对方前场三分之一的传球 ÷ 双方各自在对方前场三分之一的传球之和 × 100 | % |

**核查容差**（沿用 ADR-0005）：
- 次数必须完全相等；
- 百分比允许 ±0.5 个百分点；
- xG 允许 ±0.01；
- 指数允许 ±0.02；
- 米允许 ±0.5；公里允许 ±0.1；比值允许 ±0.1。

## 5. 单场评分

### RAT-001 计算方法（初稿，权重可调）

- 每名球员**从 6.5 起算**（与 Sofascore 公开的起算分一致，参考资料 [7]），按下表加减分，结果限制在 3.0 到 10.0 之间。
- 出场不足 10 分钟的球员不显示评分。

| 类别 | 项目 | 分值 |
|---|---|---|
| 进攻 | 进球 | +1.0 |
| | 助攻 | +0.6 |
| | 关键传球 | +0.15 |
| | 射正 | +0.1 |
| | 推进传球、推进带球 | +0.05 |
| | 成功过人 | +0.1 |
| 控球价值 | 本人事件 `threat` 之和 | × 4.0 |
| 防守 | 成功抢断、拦截 | +0.1 |
| | 封堵射门 | +0.15 |
| | 赢得对抗 | +0.05 |
| | 解围 | +0.03 |
| 门将 | 每次扑救 | +0.3 × 被扑射门的 `xg` + 0.1 |
| | 每丢一球 | −0.3 |
| 后卫 | 本队每丢一球 | −0.1 |
| 失误 | 失误（MET-014 的口径） | −0.05 |
| | 导致对方射门的失误 | −0.3 |
| | 犯规 | −0.05 |
| | 黄牌 | −0.3 |
| | 红牌 | −1.5 |
| | 乌龙球 | −1.0 |
| | 送点 | −0.8 |

- **进攻项权重较大**：这和业界一致。一项比较 WhoScored、FotMob、Sofascore 的研究发现，三家都是射正、关键传球、成功过人这类进攻数据影响最大，解围这类防守数据影响较小但稳定计入（参考资料 [8]）。
- **按位置分组标定**：为了不让后卫和门将的分数系统性偏低，200 场模拟下来，门将、后卫、中场、前锋**每组**的平均分都应在 6.6 到 6.8 之间。哪一组不满足，就调这一组主要动作（门将的扑救、后卫的防守项）的权重，不改其他组。
- **标定目标**：全部球员平均约 6.7，标准差约 0.7；进球的前锋通常在 7.5 以上（Pivot 自定），各项权重在 B07 里调整。
- **说明**：这是 Pivot 自己的评分，不能和任何比分应用的分数直接比较。上面那项研究也指出，各家评分反映的是比赛表现的不同侧面，彼此不能互换（参考资料 [8]）。
- 评分每分钟更新一次，通过 `player_stats.updated` 推送。

## 6. 场外与环境影响

### CTX-001 怎么生效

- 开球前，模拟器把比赛背景换算成一组 `ContextEffect`，写进 `MatchContext.effects`。比赛中只按这个清单生效，**不另外加隐藏的影响**。
- 每条影响作用在一个“目标”上。各个目标对应模拟器里的这些参数：

  | 目标 `target` | 作用 |
  |---|---|
  | `composure` | 被压迫时的成功率 × (1 + delta) |
  | `motivation` | 跑动强度和冲刺次数 × (1 + delta) |
  | `concentration` | 失误概率 × (1 − delta) |
  | `fitness` | 开场体能 + delta |
  | `aggression` | 犯规概率 × (1 + delta) |
  | `chemistry` | 两人之间的传球成功率 × (1 + delta) |
  | `card_risk` | 犯规后出牌的概率 × (1 + delta) |
  | `error_rate` | 关键失误概率 × (1 + delta) |
  | `stamina_decay` | 比赛中体能下降速度 × (1 + delta) |
  | `injury_risk` | 受伤概率 × (1 + delta) |

- **上限**：单条影响的绝对值不超过 0.15（格式已限制）；同一个人、同一个目标的影响加起来，绝对值不超过 **0.25**（Pivot 自定）。

### CTX-002 各类因素的默认幅度（Pivot 自定，可调）

| 来源 | 什么时候产生 | 目标和幅度 |
|---|---|---|
| 面对旧主 `former_club` | 球员的生涯里有对方俱乐部 | 积极性 +0.03 起；当初是**被放走、出场少或降薪离开**的，再 +0.03；离开时不欢而散的，再 +0.02；**客场**作战再 +0.01，最多 +0.10。研究发现面对老东家时进攻产出更多、客场更明显、被放走或出场少的球员最明显，原因主要是情绪（参考资料 [11]） |
| 老队友（同队） `former_teammate` | 两人曾在别的队一起踢过 | 两人之间的默契 +0.01 × 共事赛季数，最多 +0.05 |
| 过节 `rivalry` | 两人的关系是对头或有过节 | 侵略性 +0.05，吃牌风险 +0.05 |
| 赛事等级 `competition` | 每场都有 | 沉着 + (大赛表现 − 50) ÷ 50 × 0.02 × (重要程度 − 1) |
| 比赛意义 `stakes` | 争冠、保级、淘汰赛 | 积极性 +0.02 到 +0.04；抗压低于 40 的球员沉着 −0.02 |
| 主场气氛 `crowd` | 非中立场 | 主队积极性 + 0.04 × 上座率；客队沉着 − 0.02 × 上座率 × (1 − 抗压 ÷ 100)。主场优势主要通过这一条体现（见 CTX-003）。上座率 = 观众人数 ÷ 球场容量；加入球场信息之前，暂按观众人数 ÷ 50,000 计算，最多为 1 |
| 场外新闻 `off_field` | 赛前 72 小时内有负面新闻 | 夜店、迟归：体能下降速度 + 0.03 × 严重程度 × (1 − 职业素养 ÷ 100)，专注 −0.01 × 严重程度。开场体能**不变**，影响体现在比赛后段，因为研究显示睡眠不足和前一晚饮酒主要影响耐力，对爆发力和力量影响不明显（参考资料 [13][14]）。缺少针对足球比赛的直接研究，属于模拟假设。合同纠纷、公开批评：专注 −0.01 到 −0.04 |
| 近况 `form` | 最近五场平均评分 | 积极性 + (平均评分 − 6.7) × 0.03 |
| 疲劳 `fatigue` | 距上一场不足 4 天 | **体能不变**；影响清单记一条受伤风险 +0.15 作说明，受伤模型再直接按休息天数调整基础概率：不足 4 天时约为正常的 6 倍（可调）。研究显示一周两赛（间隔 72 到 96 小时）时跑动和冲刺没有明显下降，但受伤率约为一周一赛的 6 倍（参考资料 [12]） |
| 天气、场地 `weather` | 雨、大风、积水场地 | 全队地面传球成功率 × (1 − 0.02 到 0.05) |
| 裁判 `referee` | 每场都有 | 判罚尺度、出牌倾向直接进入犯规和出牌概率，不经过影响清单 |

### CTX-003 主场优势

- 主场优势放在**主队球员的表现**上：主队成功概率 × (1 + 0.02 × 上座率)，再加上 CTX-002 里的主场气氛。空场比赛（上座率为 0）时主场优势基本消失。
- **不设裁判偏向主队的规则**。新冠期间的空场比赛研究显示，没有观众时主场优势几乎减半甚至消失（参考资料 [9][10]）；但裁判偏向是不是主要原因，研究之间有分歧：把比赛优势考虑进去以后，犯规和黄牌上的差异明显变弱，荷兰的研究认为主要原因是主队球员自身受到了观众的影响（参考资料 [9][10]）。
- 标定目标：200 场里主胜约 45%、平约 25%、客胜约 30%（PRD 6.3）。

### CTX-004 虚构与表述

- 所有人物、俱乐部、赛事、新闻都必须是虚构的，不使用真实人名、真实事件、真实赛事品牌。
- 新闻标题只描述行为，不做道德评判；不涉及违法行为、伤病隐私和家人的具体细节。
- AI 引用场外因素时，句子必须带 `context_ids`，并且指向真实存在的影响、新闻、生涯或关系条目，否则核查员判为 `context_invalid`。

## 7. 数据质检规则

模拟器每跑完一场，都由质检脚本检查下面这些规则。任何一条不通过，这场数据就判为无效（Pivot 自定，参考专业数据商的赛后复核流程）。

| 编号 | 规则 |
|---|---|
| QA-001 | `t` 和 `seq` 都严格递增；同一个 `t` 下 `seq` 也递增 |
| QA-002 | 每个 `t` 都有且只有一帧追踪帧；每帧的球员都是当时在场的人 |
| QA-003 | 任何球员相邻两帧的速度不超过 12 米/秒；体能不会在比赛中变高（换上场的除外） |
| QA-004 | 成功传球的接球人必须是**队友**，并且在终点附近 3 米以内 |
| QA-005 | 比分等于第 1 到第 4 阶段里 `shot_outcome = goal` 的射门数，减去被 VAR 改判的，再加上乌龙球；点球大战比分等于第 5 阶段的进球数 |
| QA-006 | 每队场上人数在 7 到 11 之间；红牌后人数减一 |
| QA-007 | 换人次数不超过上限；被换下的人不再出现 |
| QA-008 | `related_event_ids` 双向一致，指向的事件都存在 |
| QA-009 | 同一控球段内的事件，`team` 只来自控球方，或者是对方没有控制球的动作（压迫、封堵、对抗） |
| QA-010 | 实际补时不短于公布的补时 |
| QA-011 | 点球大战只在比赛规则允许、而且 120 分钟后打平时出现；前 5 轮后按突然死亡规则结束 |
| QA-012 | 每条 `ContextEffect` 都指向存在的来源；同一人、同一目标的影响之和不超过 ±0.25 |
