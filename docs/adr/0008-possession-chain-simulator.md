# ADR-0008：模拟器采用控球链马尔可夫模型 + 状态快照 + 公共随机数

- 状态：已采纳
- 日期：2026-10-23
- 相关：ADR-0009、ADR-0010

## 背景

赛题要求只能用合成数据。推演需要能从比赛的任意时刻接着往下跑；评测需要能把已知的转折点植入比赛；整个模拟器必须由一个人在 1.5 天内写完并完成标定。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 控球链马尔可夫模型** | 12×8 区域网格 + 动作概率 + 体能和人数修正；单场只需毫秒级；可以做快照；参数含义清楚 | 没有球员坐标级的空间数据 |
| B. 基于物理和追踪数据的 22 人模拟 | 最真实 | 工作量大，运行慢，3.5 天内做不完 |
| C. 让 LLM 生成事件 | 文本像真的 | 无法复现；慢且贵；统计特性不可控 |
| D. 回放一份固定的合成数据集 | 零开发 | 做不了反事实推演 |

## 决策

采用方案 A。

- **状态** `MatchState`：比赛时钟、比分、控球方、球所在区域、双方在场球员（含体能）、红牌、剩余换人次数、战术参数（进攻倾向、压迫等级、阵型宽度），以及 `rng_state`（numpy PCG64 生成器的状态）。
- **每一步**：按区域和战术参数抽样一个动作（传球、带球、射门、犯规），按动作类型抽样耗时，按“实力 × 体能 × 人数”修正成功率。射门的进球概率取决于区域威胁值和对方压迫。
- **快照**：每个整分钟保存一次 `MatchState`，写入分钟文档。从快照续跑的结果逐位一致。
- **公共随机数**：推演时第 i 次的基线运行和反事实运行使用同一个种子 `seed_base + i`，两组结果成对比较，方差更小。
- **植入接口**：`PlantSpec{minute, type, team, ...}` 在指定时刻强制发生某个事件，用于评测集和 Demo 预设。
- **标定**：用 200 场模拟比赛核对场均进球（2.5 到 3.0）、射门（20 到 28）和控球率分布。标定结果写进 README。

## 后果

- **正面**：单场模拟约 10 毫秒（估算），推演可以在几秒内完成；结果可复现；评测有标准答案。
- **负面**：球场图只能展示区域级位置，回放动画是“区域到区域”的移动。
- **风险**：推演结果可能被质疑“不像足球”。缓解办法是公开标定统计和局限，并在界面上始终标注“基于合成模拟，不是预测”。
