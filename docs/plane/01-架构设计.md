### 技术摘要

Pivot 是一个事件驱动的多 Agent 系统，做三件事：从合成比赛事件流中实时发现转折点，用可复算的证据解释它，再从转折点续跑模拟、回答“假如当时不是这样”。架构上的关键决策有六个：

1. **模块化单仓 + 端口与适配器**。领域核心不依赖任何云服务。同一份代码可以跑在三种部署形态上：本地 L、云端最小 C1、云端完整 C2。砍需求时只换形态，不动代码结构（[ADR-0001]（见“架构决策记录”页 ADR-0001））。
2. **计算与生成分离**。模型写的每个数字都必须附带统计引用，由确定性的 Verifier 重算核对；不通过就打回重写，最多 2 次，之后降级为模板解释（[ADR-0005]（见“架构决策记录”页 ADR-0005））。
3. **显式工作流编排**。用 Microsoft Agent Framework 搭两条固定的链：发现链（Judge → Explainer ⇄ Verifier）和推演链（Translator → 执行器 → Comparator → Verifier）（[ADR-0004]（见“架构决策记录”页 ADR-0004））。
4. **事件骨干**。事件流走 Event Hubs，Agent 任务走 Service Bus，实时推送走 Web PubSub，存储用 Cosmos DB Serverless（[ADR-0002]（见“架构决策记录”页 ADR-0002）、[0003]（见“架构决策记录”页 ADR-0003）、[0006]（见“架构决策记录”页 ADR-0006）、[0007]（见“架构决策记录”页 ADR-0007））。
5. **可快照的控球链模拟器 + 公共随机数**。模拟器既负责生成比赛，也负责续跑推演，还能植入已知转折点作为评测的标准答案（[ADR-0008]（见“架构决策记录”页 ADR-0008））。
6. **一键部署**。azd + Bicep 创建全部资源，服务之间只用托管身份，仓库里没有任何密钥（[ADR-0013]（见“架构决策记录”页 ADR-0013））。

### 6.3 核查算法

```text
verify(draft, match, pivot):
  issues = []
  if not 1 <= len(draft) <= 3: issues += "句数越界"
  for s in draft:
    if words(s.text) > 30: issues += "超长"
    if not 1 <= len(s.evidence_ids) <= 4: issues += "证据数量越界"
    for eid in s.evidence_ids:
      e = repo.event(eid)
      if e is None or not (pivot.minute-8 <= e.minute <= pivot.minute+5): issues += f"证据 {eid} 无效"
    for c in s.claims:
      v = StatCalculator(match).compute(c.stat_ref)
      if not within_tolerance(c.value, v, c.unit): issues += f"{c.stat_ref} 写 {c.value}，实为 {v}"
    if has_direction_word(s.text) and direction_mismatch(s, StatCalculator): issues += "方向词不符"
    if has_significance_word(s.text) and not ci_non_overlap(...): issues += "显著性措辞不成立"
    if banned_terms(s.text): issues += "禁用词"
  return Verdict(pass=not issues, issues=issues)
```

容差：计数精确相等；百分比 ±0.5 个百分点；xG ±0.01；势头指数 ±0.02。通过后，上屏数字一律替换为计算值。

### 6.4 Prompt 与结构化输出约定

- 系统提示包含：角色、受众（分析师，英文界面）、统计词表、禁用词表、输出 JSON Schema、2 个 few-shot 示例（取自评测种子）。
- 模型输出一律使用结构化输出（JSON Schema 严格模式）；Pydantic 校验失败视同核查不通过。
- 所有 prompt 放在 `apps/worker/prompts/*.md` 里做版本管理，trace 中记录 prompt 的哈希。
- 语言：界面和解释都用英文，面向国际评委；文案集中管理，方便以后做多语言。

```python
class MatchEvent(BaseModel):
    schema_version: Literal[1] = 1
    match_id: str
    seq: int                                  # 同一场比赛内单调递增
    event_id: str                             # "m063-s01042"，界面显示为 #1042
    t: int                                    # 比赛时钟，单位秒，0–5400
    period: Literal[1, 2]
    type: EventType                           # pass carry shot goal tackle interception pressure foul card substitution kickoff period_end
    team: Side                                # home | away
    player_id: str | None
    from_zone: tuple[int, int] | None         # 12×8 网格
    to_zone: tuple[int, int] | None
    outcome: Literal["success", "fail"] | None
    xg: float | None                          # 只有射门才有
    threat: float                             # 这个事件带来的威胁增量
    meta: dict[str, str] = {}                 # 牌色、换人的上下场球员等

class StatRef(BaseModel):
    metric: StatMetric                        # 统计词表，初版 15 项
    team: Side
    window: tuple[int, int]                   # 左闭右开的分钟区间

class Claim(BaseModel):
    value: float
    unit: Literal["count", "pct", "xg", "index"]
    stat_ref: StatRef

class ExplanationSentence(BaseModel):
    text: str                                 # 不超过 30 个英文单词
    evidence_ids: list[str]                   # 1 到 4 个
    claims: list[Claim]

class Pivot(BaseModel):
    pivot_id: str
    match_id: str
    minute: int
    direction: Side                           # 势头转向的一方
    severity: Literal[1, 2, 3]
    status: Literal["pending", "confirmed", "rejected", "degraded"]
    trigger_event_ids: list[str]
    headline: str                             # 卡片标题，≤ 8 个英文单词，不得含数字
    explanation: list[ExplanationSentence]
    verifier_attempts: int
    chain_id: str                             # 与 OpenTelemetry trace id 相同

class ScenarioSpec(BaseModel):
    type: Literal["cancel_substitution", "move_substitution", "remove_red_card", "remove_goal", "change_press"]
    pivot_id: str
    target_event_id: str | None
    at_minute: int                            # 从这一分钟的快照开始续跑
    params: dict[str, int | str] = {}
    n_runs: Literal[200, 500, 1000] = 500
    seed_base: int

class OutcomeDist(BaseModel):
    home_win: float
    draw: float
    away_win: float
    ci95: dict[str, tuple[float, float]]      # Wilson 区间

class SimResult(BaseModel):
    scenario_id: str
    baseline: OutcomeDist
    counterfactual: OutcomeDist
    significant: dict[str, bool]              # 置信区间不重叠才为 True
    explanation: list[ExplanationSentence]
    runtime_ms: int
    executor: Literal["local_pool", "aca_jobs"]
```

## 8. 可靠性与故障模式

| 故障 | 如何发现 | 如何处理 | 用户看到什么 |
|---|---|---|---|
| 模型超时或限流（429） | SDK 异常 | 指数退避重试 2 次，然后降级为模板 | 转折点卡片上显示 “Auto summary” 标记 |
| 核查连续不通过 | Verifier 返回不通过 | 重写 2 次后降级 | 同上；轨迹面板显示每次被拒的原因 |
| Worker 处理到一半崩溃 | 消息锁定过期 | Service Bus 重新投递；用确定性 ID 判断，已完成的步骤直接跳过 | 转折点上屏晚几秒 |
| 毒消息 | 投递次数超过上限 | 进入死信队列，App Insights 告警 | 卡片 60 秒后从“待确认”转为“降级” |
| Functions 批处理失败 | 运行时重试 | 从检查点重放；upsert 加 `seq` 去重 | 无感 |
| Web PubSub 断线 | 客户端 onclose | 指数退避重连，然后用 `sinceSeq` 补齐 | 顶栏短暂显示 “Reconnecting…” |
| 模拟器崩溃 | 健康探针失败 | Container Apps 自动重启；比赛从最后一个整分钟快照恢复 | 比赛状态显示 “Resumed at 63′” |
| Cosmos 限流（429） | SDK 重试 | 按分钟批量写入；SDK 内置重试 | 无感 |
| 推演请求过多 | API 计数器 | 返回 429 和 Retry-After；排队 | “Lab is busy, retry in 20s” |
| 用户输入被内容安全拦截 | Content Safety 判定 | 拒绝解析 | 提示改写，并给出 3 个示例 |
| 区域级故障 | — | 不在范围内，单区域部署 | 视频作为兜底 |

## 9. 安全与合规

| 方面 | 措施 |
|---|---|
| 身份 | 一个用户分配托管身份，按服务授予数据面角色（见 ADR-0013）；本地开发用 DefaultAzureCredential |
| 密钥 | 仓库中零密钥；GitHub 秘密扫描与推送保护；部署用 OIDC 联合凭据 |
| 网络 | 只有 API 和 Web 对公网开放；simulator 和 worker 只有内部入口；Cosmos 和 Service Bus 允许 Azure 服务访问（时间不够做私有终结点，作为已知限制写进文档） |
| 滥用防护 | 每 IP 限流；全局推演配额；请求体大小上限；CORS 白名单只放 Web 的域名 |
| 内容安全 | 用户输入和模型输出都经过 Foundry 内容安全；禁用词表（博彩、绝对化措辞） |
| 数据 | 只有合成数据；虚构球队和球员；不收集个人信息；没有账号体系 |
| 品牌与版权 | 不使用英超标识；视频不用版权音乐；界面文案不暗示官方合作 |
| 供应链 | 依赖锁定（uv.lock、pnpm-lock）；开启 Dependabot 安全更新 |

## 10. 可观测性

| `dlq_depth` | 0 | Service Bus 指标，配置告警 |

### 13.2 模块边界与依赖规则

1. `apps/*` 只依赖 `packages/*`；`pivot_core` 不依赖任何其他包（由 import-linter 检查）。
2. Azure 适配器只在每个应用的组合根（`apps/*/bootstrap.py`）里按 `PIVOT_PROFILE` 实例化。
3. 每个端口至少有两个实现：`local`（含测试用的假实现）和 `azure`，两者共用一组契约测试。
4. `apps/web` 只依赖 `packages/contracts` 生成的类型和 REST / WebSocket 接口。

### 13.3 契约优先流程

1. 修改 `pivot_core/domain` 中的模型 → 运行 `uv run scripts/export_contracts.py` 生成 JSON Schema → 运行 `pnpm --filter web gen:types` 生成前端类型。
2. **10/23 20:00 冻结契约**。冻结后只允许新增可选字段；其他任何变更都要在群里通知全员。
3. C 在冻结后立刻用 `eval/fixtures/demo-1021.json`（B 当晚产出）开发前端，不必等后端完成。
