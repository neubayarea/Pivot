# 合体测试清单（T03 本机 · T04 线上）

按 2 分钟演示的路线排：打开首页 → 选比赛 → 回放 → 势头曲线 → 转折点卡片 → 「假如」实验室 → 演示比赛的三个转折点。
每一条写了怎么操作、应该看到什么，以及在本机（T03）和线上（T04）各怎么做。最后一节是每次试走的记录。

- 线上：https://pivot.in-stacks.com （甲骨文服务器 2 核，`pivot_api.single` 一个进程，AI 用 Azure Foundry，AI 结果存 Cosmos DB）
- 本机：http://127.0.0.1:8000 （同一个程序，假流水线，不连 Azure）
- 演示比赛：`M-seed-41`（预设 `demo-1021`，HBC 1–0 ROV），埋了三个转折点：38′ Rovers 红牌 → 势头倒向 HBC；65′ HBC 换人后退守 → 倒向 ROV；85′ HBC 换人 → 倒向 HBC。

> #179（B12，改模拟规则）合并后模拟版本号会变，模拟比赛和 AI 结果会重新生成。合并后照这份清单再走一遍。

## 0. 准备

### 本机（T03）

需要 [uv](https://docs.astral.sh/uv/) 和 pnpm。在仓库根目录：

```bash
uv sync && pnpm install && pnpm --filter web build
```

```bash
PIVOT_PIPELINE=fake PIVOT_SIM_MATCHES=1 PIVOT_WHATIF_WARM=0 PIVOT_RESULTS_BACKEND=files PIVOT_DATA_DIR=.pivot-data uv run python -m pivot_api.single
```

- `PIVOT_PIPELINE=fake`：不调模型，解释全是模板文字（这是对的，不算失败）。不要在本机填真实的 Azure 设置。
- `PIVOT_SIM_MATCHES=1`：只生成一场模拟比赛（种子 101），几秒钟就好；不设就是 6 场。
- `PIVOT_WHATIF_WARM=0`：启动时不预先算「假如」，省 CPU。
- `.pivot-data/` 已在 `.gitignore` 里，别提交（见 [比赛数据放在哪](../match-data.md)）。
- 换端口：前面加 `PORT=8011`。

看到 `Uvicorn running on http://127.0.0.1:8000` 后检查：

```bash
curl -s http://127.0.0.1:8000/healthz
```

```bash
curl -s http://127.0.0.1:8000/api/sims
```

应该是 `{"status":"ok"}`，以及 `ready` 等于 `total`。

### 线上（T04）

```bash
curl -s https://pivot.in-stacks.com/healthz
```

```bash
curl -s https://pivot.in-stacks.com/api/sims
```

`ready` 应等于 `total`（6），`failed` 为 0。

- 服务器只有 2 核：「假如」只点**已经提前算好**的芯片（每个演示转折点的前两个，`PIVOT_WHATIF_WARM=2`），不要连续点很多个新问题。
- 浏览器以前打开过网站的话，会记住上次选的比赛（`localStorage` 的 `pivot.match`），所以首页不一定是演示比赛。录演示前用无痕窗口，或者地址后加 `?match=M-seed-41`。
