> 2026-10-23 · 供开工会讨论 · 依据：[Official Rules](https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md)（下文 §编号均指规则章节）

## 2. 规则要求 vs 我们的方案

§4.1 (i) 要求一条五段流水线：**Ingest → Interpret → Explain → Render → Personalize**。

| 规则要求 | 我们现在 | 判断 |
|---|---|---|
| **Ingest**：实时摄入事件（传球、射门、抢断、球权转换、压迫、比赛元数据） | 模拟器 + 事件流 | ✅ |
| **Interpret**：转成统计、模式和背景 | 15 项统计、势头 EWMA、CUSUM 变点 | ✅ |
| **Explain**：解释为什么重要，而不只是报告发生了什么 | Judge → Explainer ⇄ Verifier | ✅ 强项 |
| **Render**：能和比赛同屏；有时间戳、机器可读，能作为直播画面的同步图形叠加层 | S1 看板有内容，但没按"叠加层输出"设计 | ⚠️ 补包装即可 |
| **Personalize**：同一份情报，给爱看数据的分析师和普通球迷两种真正不同的体验；主队、球员、球员聚焦模式、语言偏好、关注的单项指标 | **没有**。PRD 把账号体系列为 Out of scope；架构 §6.4 定为"界面和解释都用英文" | ❌ 最大缺口 |
| **Narrative**（§4.1 iii）：关键叙事、球员表现背景、里程碑、**赛后集锦 recap** | 没有 | ❌ |
| **Multi-language**（§4.1 vi）：多语言自然语言输出 | 只有英文 | ❌ |
| **Explainability**（§4.1 iv）：控制 vs 混乱、压迫变化、比赛节奏 | 势头、压迫已覆盖；"节奏"可以从现有统计派生 | ✅ |
| **实时指标**（§4.1 ii，"consider"）：球员名标注、传球距离/准确率/难度、球速/射速 | 模拟器是 12×8 区域网格，没有坐标、距离和速度 | ⚠️ 建议项，可选 |
| What-if 推演 | 我们的核心亮点 | 规则**未要求**，属于创新加分 |

**评审标准里点名但我们没用的 hero 技术**（§6.2）：Azure MCP、GitHub Copilot Agent Mode、Fabric、GitHub SDK/CLI。Agentic 一项明确写了 "MCP integration"。

## 4. 时间从哪里来

现在每条线 Must 已占 90% 到 100%，补的东西需要让出时间：

- **截止延后一天**：真实截止是 10/27 23:59 PT，可以把 M5 提交挪到 10/27 白天，多出约 8 到 10 小时。
- **What-if 不砍**：它是 Pivot 和其他参赛作品拉开差距的核心亮点，保留为 Must，按原计划推进。
- **Should 里先放弃 S2**（Event Hubs + Functions，8 h）：Cloud Native 奖可以靠 Container Apps、Service Bus、Cosmos DB、Web PubSub 来讲。

## 5. 要改的其他地方

- **部署要一直开到 11/10**：§4.8 要求评审期内能免费访问可运行的项目，评审期 10/27 到 11/10。PRD 写的"提交后立刻缩容"要改；云预算按多跑两周重估，或者准备一个静态演示版兜底。
- **数据格式（B01）今晚定稿前要把个性化用的字段加进去**：例如 `audience`（analyst / fan）、`language`、`focus_team`、`focus_player`，以及 `Recap` 和 `Overlay` 两种数据。定稿后只能加可以不填的字段，所以今天就要定。
- **Demo 脚本**：2 分钟里要出现一次"同一个转折点，分析师版 vs 球迷版"，再加一次语言切换。这是赛道契合度（20%）最直观的证据。
- **README / Pitch**：按五段流水线组织，逐段对应规则 §4.1 (i)。
