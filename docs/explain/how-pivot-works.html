Pivot 是怎么运转的？

我们先造一场假比赛，让电脑找出比赛在哪一刻变了，再让 AI 用证据讲清楚为什么，最后让你问一句「如果当时不是这样呢？」

四张图看完就懂。10/25 已按实际上线的样子更新：网站跑在一台服务器上，只有 AI 模型和 AI 结果的档案柜在微软云上。工程细节在 Pivot 架构设计。

工程师说的在图里是一句话解释
Simulator模拟球场用规则和随机数“踢”出一场假比赛。比赛规定不能用真实数据
Event Hubs（原计划）传送带把比赛动作按先后顺序一条条送过去。实际上线时在程序内部传，没有用这个服务
CUSUM势头计里的报警器曲线持续往一边跑，它就会响
Service Bus（原计划）任务单活儿排队等着做。实际上线时在程序内部排队
Agent解说团里的一个人判定员、写稿员、核对员，各管一件事
FoundryAI 大脑我们向微软借用的 AI 模型（gpt-4.1-mini），附带考试和监控工具
Cosmos DB档案柜AI 写的转折点、解释、工作记录和「假如」的结果放在这里。重启后直接读回，不用再让 AI 重写
服务器硬盘比赛文件模拟比赛的事件和每秒的跑位放在服务器硬盘上，不进 GitHub
Web PubSub（原计划）广播喇叭有新消息，就同时推到所有人的屏幕。实际上线时用程序自带的 WebSocket
Dokploy工位我们的程序干活的地方：甲骨文云上的一台服务器。推送到 main 就会自动更新
