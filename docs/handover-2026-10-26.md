### 3.1 "假如"提前算好、存成文件，服务器直接读：**草稿** PR #246（分支 `b/Bx11-whatif-fixture`，关闭 #218）
- **为什么要做**：线上服务器只有 2 个核，启动时现算"假如"要好几分钟。#238 换了转折点以后，线上缓存的结果全部失效，要重新算。
- **做法**：在 12 核的电脑上把 3 个转折点的**所有**"假如"选项都算好，写进 `eval/fixtures/demo-1021.whatif.json`。服务器启动时读这个文件，请求对得上就马上返回结果。
- **状态**：代码已经写完：生成脚本 `scripts/make_whatif_fixture.py`，服务器读文件的部分，5 个测试。**但结果文件里现在只算了 1 个"假如"**，应该有 3 个转折点 × 5 个选项 = 15 个，每个还要分 200 次和 500 次两种。所以 5 个测试里有 3 个会失败，要等文件算满才会通过。已经在 #218 下面留言说明由这边接手。Docker 的 API 那一层本来就复制了 `eval/fixtures`，不用改。
- **接手时要做**：
  1. 在**多核的电脑**上生成文件（在 2 核服务器上跑要 4–6 小时，不要在服务器上跑）：
     ```bash
     git switch b/Bx11-whatif-fixture
     uv run scripts/make_whatif_fixture.py --list              # 先看会算哪 15 个

     uv run scripts/make_whatif_fixture.py --table             # 打印结果表，挑视频里用哪个
     ```
     12 核大约要：15 个 × 200 次约 30 分钟，再加 500 次约 75 分钟。时间不够就只算 `--runs 200`。
  2. 跑测试，全过以后提交文件，把 PR 从草稿改成可以合并：
